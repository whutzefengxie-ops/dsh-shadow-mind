# v0.1.10 — DSH 0.2.2-rc.3 compatibility

Targets DSH **0.2.2-rc.3**, source commit `38a6a5c965aa99ab525161efb7cc5cf1fe62fced`, with Node.js **>=24.9.0**.

v0.1.9 declares the exact rc.2 engine and is rejected by rc.3's plugin compatibility gate. This release updates the engine, DSH peers, and CI pin to rc.3. The consumed Agent, Subagent, tool execution, settings, and conversation contracts are unchanged. The plugin's `src/` and prebuilt `lib/` are identical to v0.1.9, including the browser bundle.

## Install

Pin the matching DSH prerelease explicitly:

```sh
npx @deepseek-ai/dsh@0.2.2-rc.3 plugin --profile web add github:whutzefengxie-ops/dsh-shadow-mind#v0.1.10
```

Alternatively, download `whutzefengxie-ops-dsh-shadow-mind-0.1.10.tgz` and `SHA256SUMS.txt`, verify the SHA-256, and pass the absolute tarball path to `plugin --profile web add`. Restart the selected profile. No version exemption is required.

For Desktop, confirm that the bundled CLI reports **0.2.2-rc.3**, quit the app, and use its actual home:

```powershell
$env:DSH_HOME = '<actual Desktop DSH_HOME>'
& 'G:\DeepSeek Harness\resources\runtime\cli\bin\dsh.cmd' --version
& 'G:\DeepSeek Harness\resources\runtime\cli\bin\dsh.cmd' plugin --profile desktop add '<absolute tarball path>'
```

Reopen the app, check Plugins and Settings → Built-in Plugins → Shadow Mind, and verify a real file-reading turn produces a review. Web and Desktop profiles are managed independently.

## Validation

- The official rc.3 `evaluatePluginCompatibility` rejected the v0.1.9 manifest with unmet `engines.dsh`. The v0.1.10 manifest passed the same check without an exemption.
- Full `pnpm run check` passed on Windows against the pinned rc.3 source: 35 test files, 232 passed and 6 platform-specific tests skipped, Host and Client typechecks, Typert consistency, build, and bundle syntax checks. Rebuilding produced no changes in `lib/`.
- The installed Windows Desktop bundled CLI reported rc.3 and installed the package into an isolated Web profile. Its packaged runtime and Web client loaded the Shadow settings tab and saved a changed collapse setting.
- A real browser prompt on that installed runtime invoked `get_shadow_config` and `read`. Shadow independently invoked `read` and `structured_output`; every child tool result succeeded. The anchored report was visible in its conversation card and triggered the root follow-up.
- Persisted child request headers recorded `deepseek-official/deepseek-flash`: planning had no tools; investigation had exactly `glob`, `grep`, `read`, and `structured_output`, with `startsSeries: true`.

The packaged runtime was exercised through its bundled CLI and Web interface. The Electron desktop window itself was not driven. Successful acceptance used isolated homes and an explicitly owned workspace; daily profile files, Session history, and stored credentials were not modified. Other DSH versions are not claimed compatible; use v0.1.9 for rc.2.

## Rollback

Preserve the previous package, profile manifest and patch, and Shadow definitions before upgrading. Stop the selected profile or quit Desktop, reinstall the previous plugin together with its matching DSH version, and restart. Preserve Session history and credentials.
