# v0.1.9 — DSH 0.2.2-rc.2 compatibility

Targets DSH **0.2.2-rc.2**, source commit `ddac96760b6edf8fa0fe17cbdcf0b512f4c12b2c`, with Node.js **>=24.9.0**.

DSH moved activation task fields out of the nested `request` object. v0.1.8 therefore fails to start a review on rc.2 because the runtime cannot read its parent. v0.1.9 passes the task fields at the activation boundary while retaining the existing review conditioning, local structured-output ownership, tool allowlist, selected model, caller delivery, and cancellation behavior. The exact engine and peer versions and CI source pin now target rc.2.

## Install

Use the immutable GitHub tag with the matching DSH CLI:

```sh
npx @deepseek-ai/dsh@0.2.2-rc.2 plugin --profile web add github:whutzefengxie-ops/dsh-shadow-mind#v0.1.9
```

Alternatively, download `whutzefengxie-ops-dsh-shadow-mind-0.1.9.tgz` and `SHA256SUMS.txt` from the Release, verify its SHA-256, and install the absolute tarball path with `plugin --profile web add`. Restart the profile after installation. No version exemption is required.

For Desktop, first confirm that its bundled runtime is **0.2.2-rc.2**, fully quit the app, and use its bundled CLI with the actual Desktop home:

```powershell
$env:DSH_HOME = '<actual Desktop DSH_HOME>'
& 'G:\DeepSeek Harness\resources\runtime\cli\bin\dsh.cmd' plugin --profile desktop add '<absolute tarball path>'
```

Reopen the app and verify a file-reading root turn completes a Shadow review. The bundled CLI manages Desktop's own profile; a Web install does not update Desktop.

## Validation

- Before the fix, 14 provider and assembled-flow integration tests failed against rc.2 with an undefined activation parent. After the fix, all 14 passed.
- Full `pnpm run check` passed on Windows: 35 test files, 232 passed and 6 platform-specific tests skipped, Host and Client typechecks, Typert consistency, build, and bundle syntax checks. The prebuilt browser bundle reproduced without changes.
- The package tarball installed into isolated rc.2 SDK and Web profiles without any compatibility exemption. No daily profile, Session history, or stored credential was modified.
- A real `deepseek-official/deepseek-v4-flash` root invoked `get_shadow_config` and `read`. Its Shadow independently invoked `glob`, `read`, and `structured_output`; every child tool result succeeded. The accepted, anchored gap report reached the root and triggered its follow-up.
- Persisted child requests contained no tools during planning, then exactly `glob`, `grep`, `read`, and `structured_output` during investigation.
- A fresh SDK process resumed the same persisted Session and correctly recalled the report and root follow-up without calling tools.
- The rc.2 Web settings tab loaded in Chromium, rendered the saved definition, and persisted `collapsedByDefault: false`. After restarting the Web process, Chromium still displayed that setting, exactly one accepted report card, and the root follow-up without page errors.

The installed Desktop on this machine still uses rc.1 and was left unchanged. A packaged rc.2 Desktop installation was not tested; the real runtime and browser acceptance above used the pinned rc.2 source build with isolated data. Use v0.1.8 for DSH 0.2.2-rc.1. Other DSH versions are not claimed compatible.

## Rollback

Before upgrading, preserve the previous plugin package, profile manifests and patches, and Shadow definitions. Fully stop the selected profile or quit Desktop, reinstall the previous plugin with its matching DSH version, and restart. Keep Session history and credentials intact.
