# v0.1.5 - Shadow compatibility with npm DSH 0.2.0-rc.2

Shadow v0.1.3/v0.1.4 waits for the removed Client `settingsScope` service and calls the removed Host `settings.register` API. On npm DSH `0.2.0-rc.2`, this prevents activation.

This release uses Client `configForms` and Host profile-backed volatile Config fields. Settings are addressed by the actual `shadow-mind-runtime` entry id, save through `SettingsForms`, update the existing runtime, and restore after restart. The release also updates the removed icon and message/content contracts.

## Compatibility

- Supported DSH version: **0.2.0-rc.2**, the current npm `latest` release at validation time.
- DSH source and CI pin: `639ed015397290b3745d163aafe02ffee4aa3f84` (`dsh-v0.2.0-rc.2`).
- DSH peer versions are exact; older settings APIs and other unverified versions are not claimed as supported.

## Installation

```sh
npx @deepseek-ai/dsh@0.2.0-rc.2 plugin --profile web add github:whutzefengxie-ops/dsh-shadow-mind#v0.1.5
npx @deepseek-ai/dsh@0.2.0-rc.2 web
```

Restart the Web process after upgrading. Existing Shadow definitions remain in `$DSH_HOME/shadow-minds`.

- `pnpm run check`: 32 test files, 218 tests, Host and Client typechecks, Typert consistency, build, and bundle syntax checks.
- Real profile regression covers live writes without remounting, optional-field clearing, and persisted preferences after restart.
- Release tarball installs and starts using the npm DSH CLI in an isolated home; authenticated Shadow catalog and model RPCs succeed.
- The shipped browser bundle activates through the DSH Client gateway and registers settings and conversation contributions.

The package is distributed through the immutable GitHub tag and the attached `.tgz`, matching the repository's existing release installation path.
