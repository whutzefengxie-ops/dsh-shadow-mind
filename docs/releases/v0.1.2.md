# v0.1.2 — Shadow children start again on the current Session API

A runtime patch that removes the unpublished-setup registry lookup which failed every Shadow run on DSH 0.1.5, restores the live degenerate-output watchdog, and updates the test fixtures, client bundle, and typert artifacts for the current harness.

> **中文摘要**：v0.1.2 修复"每次 Shadow 运行都在 start 阶段失败"的缺陷。v0.1.1 在 setup 内查询 `ctx.agents`，而 dsh 的 agent factory 是在 setup 完成后才发布 session/agent，因此该查询必然返回 `undefined`（`SUBAGENT_START_FAILED` / `Shadow child agent <id> not found`）；现在改为直接使用 setup 已经收到的 `child`。同时把退化输出看门狗改回进程内 `agent/assistant-stream` 实时帧——持久化的 `assistant/attempt` 要等整轮结束后才提交，无法实时掐断失控输出（修复前该用例会跑满 4GB 堆 OOM）。另外适配当前 Session API 的测试夹具、客户端 bundle 的 `dsh-brand` 内联、以及已漂移的 typert 产物。

## Why

The v0.1.1 session-API compatibility change introduced two defects:

1. **Registry timing.** `attachDegenerateOutputGuard()` resolved its child through `childCtx.agents.get(childId)`. The agent factory awaits unpublished setup **before** inserting or announcing either the session or the agent, so that lookup always returned `undefined` and threw `Shadow child agent <id> not found`. Every Shadow run therefore ended at the `start` stage with `SUBAGENT_START_FAILED`. Setup already receives the `Agent` as its second parameter; that binding is the only correct source before publication.
2. **Dead watchdog.** Chunk observation had moved to the durable `assistant/attempt` event, which is committed only after the whole attempt has streamed. A repetition loop or output flood could never be cut in flight, so a stuck child occupied its slot until the run timeout. Before the fix the flood test exhausted a 4 GB heap after 168 s; observing the process-local `agent/assistant-stream` frames again settles it in milliseconds.

## Fix

- `attachDegenerateOutputGuard()` and `attachThinkFirst()` take the setup-provided `Agent`; no registry access happens during setup.
- The watchdog consumes live `agent/assistant-stream` chunk frames; the durable `session/event` bus still supplies the `tool/call` and `step/end` / `turn/end` progress signals that reset the per-stretch budgets.
- Test fixtures follow the current Session API: `session.snapshotEvents()`, `await ctx.agentLoop.create(...)`, `SessionSeq`-branded compaction ranges, `assistant/message` events carrying their `stream`, child stubs exposing `session.header` plus `snapshotEvents()`, and a surfaced `isError` block wherever a tool result carries internal error identity.
- The client bundle inlines `@deepseek-ai/dsh-brand`, the stateless branded-primitive layer `@deepseek-ai/dsh-session` now imports.
- Regenerated the committed typert artifacts, whose descriptor `sourceLocation` lines had drifted from `src/runtime/index.ts`.

## Install

```sh
dsh plugin --profile web add github:whutzefengxie-ops/dsh-shadow-mind#v0.1.2
```

The harness loads the plugin at process start, so restart the `dsh web` process after installing. Roll back with `#v0.1.1`.

## Known limits

- **npm registry publish is deferred**: the dsh client packages this bundle peers against are not on npm yet. Install from GitHub (above).
- **The v0.2.x line is superseded**: `main` previously tracked the DSH `0.1.2-alpha.3` baseline, whose Session API (`session.events`, `Context.agent`, `assistant/chunk`) no longer exists on the current harness. This release merges the continuously verified v0.1.x lineage back into `main`; the v0.2.0/v0.2.1 notes remain archived under `docs/releases/`.
